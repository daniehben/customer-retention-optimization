## Sanity checks to run after build

### J.1 Activation feed matches KPI selected counts

```sql
SELECT
  e.scenario_id,
  e.decision_month,
  COUNT(*) FILTER (WHERE e.final_selected_flag = 1) AS selected_from_feed,
  MAX(k.selected_customers) AS selected_from_kpi
FROM churn.v7_e_activation_feed_customers e
LEFT JOIN churn.v7d_decision_kpis_scenario_month k
  ON e.scenario_id = k.scenario_id
 AND e.decision_month = k.decision_month
GROUP BY 1,2
HAVING COUNT(*) FILTER (WHERE e.final_selected_flag = 1) <> MAX(k.selected_customers);
```

Expected: **0 rows**

```sql
SELECT COUNT(*) AS champion_rows
```

# What Phase 7 results mean (clean takeaway)

1. **Official policy works:** p95-buffer selection yields **zero p95 overspend months** across all scenarios.
2. **Tail risk exists and is monitored:** raw overspend remains in some months and is explicitly acceptable under documented governance.
3. **Scenario sensitivity is clear:**

   * Best total value: **LIFT_125**
   * Best ROI: **MARGIN_30**
   * Worst performance: **LIFT_075**
4. **Program scale is limited by economics, not budget:** expected spend uses ~10–15% of budget pool → the constraint is viable targets, not funding.
5. **Activation is simple and consistent:** only `free_shipping` is selected → reduces operational complexity.
