# Phase 7F–7I — Scenario comparison and selection of the overall champion

## Purpose

Once decisions are produced under each scenario, the business needs:

> “Which scenario should we run as the baseline policy assumption?”

This was answered in two layers:

* a **global leaderboard** (7F)
* a **monthly winner** view (7G)
* a **winner stability rollup** (7H)
* a **single champion** view (7I)

---

## 7F `churn.v7f_scenario_rollup` — Scenario leaderboard (all months)

### What it does

Aggregates monthly KPIs (7D) up to scenario-level totals:

* total net EV
* total spend
* weighted ROI
* utilization
* number of raw-overspend months
* whether any p95 overspend occurred (hard disqualifier)


---

## 7G `churn.v7g_scenario_rollup_month` + `v7g_scenario_winner_month` — Winner per month

### What it does

Ranks scenarios **within each month**, using:

* p95 overspend = hard gate
* then net EV
* ROI, utilization
* then raw overspend / tail exposure preference

This answers:

* “Does the champion win consistently, or is it volatile?”

---

## 7H `churn.v7h_scenario_winner_rollup` — Winner stability summary

This aggregates the monthly winners to compute:

* months won
* win rate
* value delivered during winner months
* risk flags during winner months
* coverage across all months

This is the bridge to final champion selection.

---

## 7I `churn.v7i_scenario_winner_final` — Single champion

### What it does

Selects one row (the champion) using:

1. must have zero p95 overspend any month
2. highest win_rate
3. highest net EV in months it wins
4. ROI/utilization as tie-breakers
5. fewer raw overspend months preferred

This yields the final “business-ready decision”:

* **which scenario is most defensible to run**

---

## Dependencies / Build Order

**Upstream dependencies (must exist first)**

* `churn.v7d_decision_kpis_scenario_month` *(Phase 7D)*
* `churn.v_7a_scenario_params` *(scenario parameter metadata for explainability)*

**This file creates (run in this order)**

1. `churn.v7f_scenario_rollup` *(overall scenario leaderboard across all months)*
2. `churn.v7g_scenario_rollup_month` *(scenario ranks per month)*
3. `churn.v7g_scenario_winner_month` *(winner rows per month)*
4. `churn.v7h_scenario_winner_rollup` *(winner stability summary)*
5. `churn.v7i_scenario_winner_final` *(single champion scenario)*

**Downstream consumers**

* CSV exports for scenario leaderboard + winner logic
* Executive summary “which scenario should we run?” narrative

## Sanity checks to run after build

**7F.1 Exactly one row per scenario**

```sql
SELECT COUNT(*) AS scenarios
FROM churn.v7f_scenario_rollup;
```

Expected: **6 rows**.

**7G.1 One winner per month**

```sql
SELECT
  decision_month,
  COUNT(*) AS winners
FROM churn.v7g_scenario_winner_month
GROUP BY 1
HAVING COUNT(*) <> 1;
```

Expected: **0 rows**.

**7H.1 Winner rollup covers all scenarios**

```sql
SELECT scenario_id, months_won, months_covered, win_rate
FROM churn.v7h_scenario_winner_rollup
ORDER BY win_rate DESC;
```

Expected: includes **all scenarios** (some may have `months_won = 0`).

**7I.1 Single champion only**

```sql
SELECT COUNT(*) AS champion_rows
FROM churn.v7i_scenario_winner_final;
```

Expected: **1**.

**7I.2 Champion must pass hard gate**

```sql
SELECT *
FROM churn.v7i_scenario_winner_final
WHERE any_p95_overspend_any_month = 1;
```

Expected: **0 rows** (champion must be eligible).
